Every tool is marked `readOnlyHint: true`, returns both `structuredContent` and a JSON text copy, and is limited to the project of the connection.

Returned text (test titles, error excerpts, incident summaries) comes from your systems and is treated as **untrusted data**: tool descriptions tell the AI never to follow instructions found in it.

## Tools

| Tool | Needs permission to view | Arguments | Returns |
|---|---|---|---|
| `get_context` | project | none | The connected project and your role |
| `list_tests` | tests | `limit`, `cursor` | `id`, `title`, `type`, `priority`, `updatedAt` (no scripts) |
| `get_test` | tests | `id` | Metadata and description for one test (no script) |
| `list_jobs` | jobs | `limit`, `cursor` | `id`, `name`, `jobType`, `status`, `cronSchedule`, `lastRunAt`, `nextRunAt` (no alert settings) |
| `list_runs` | jobs | `limit`, `cursor` | Recent runs, newest first: `status`, `trigger`, `location`, `durationMs`, start and end |
| `get_run` | jobs | `id` | One run plus a redacted, truncated `error` excerpt |
| `list_monitors` | monitors | `limit`, `cursor` | `name`, `type`, `target` (scheme and host only), `status`, `lastCheckAt` |
| `list_incidents` | incidents | `limit`, `cursor` | `number`, `title`, `severity`, `status`, `createdAt`, `resolvedAt` |
| `get_incident` | incidents | `id` | One incident with its root-cause summary |
| `prepare_local_authoring` | project | none | CLI commands for creating or editing tests (this server never writes) |

## Paging

List tools accept `limit` (1 to 50, default 20) and `cursor`. When more results exist the response has a `nextCursor`; pass it back as `cursor` for the next page. `id` and `cursor` values are UUIDs.

## Errors

| Code | Meaning |
|---|---|
| `forbidden` | Your role cannot view this kind of resource |
| `not_found` | No such item in the connected project |
| `internal_error` | The request failed; try again |

Invalid arguments (an `id` that is not a UUID, or a `limit` outside 1 to 50) return a validation error. Connection-level problems return HTTP errors instead: `401` (sign in again), `403` (`access_denied` when access was removed, or `insufficient_scope`), `404` (MCP is off), `405` (only POST is accepted), `413` (request over 1 MB), `500` (`server_error`).

`get_incident` takes the incident `id` from `list_incidents`, not the incident number.

## Not available

Writes of any kind, test scripts, variable values, run reports and artifact files, and an incident timeline. Use the [CLI](/docs/cli/commands) for authoring and deploys.
