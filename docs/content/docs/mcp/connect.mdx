You need access to the project you want to share and a server with MCP turned on. Self-hosting? Follow [Self-hosted](/docs/app/deployment/self-hosted#connecting-ai-tools-mcp-off-by-default) first. Replace `https://your-supercheck-host` with your URL (`http://localhost:3000` for a local install).

## Add the server

<Tabs items={['Claude Code', 'Cursor', 'VS Code', 'Other clients']}>
<Tab value="Claude Code">

```bash
claude mcp add --transport http supercheck https://your-supercheck-host/api/mcp
```

Then run `/mcp` inside Claude Code, choose **supercheck**, and sign in.

</Tab>
<Tab value="Cursor">

Add to `.cursor/mcp.json` (project) or `~/.cursor/mcp.json` (all projects):

```json
{
  "mcpServers": {
    "supercheck": { "url": "https://your-supercheck-host/api/mcp" }
  }
}
```

</Tab>
<Tab value="VS Code">

Add to `.vscode/mcp.json`:

```json
{
  "servers": {
    "supercheck": { "type": "http", "url": "https://your-supercheck-host/api/mcp" }
  }
}
```

</Tab>
<Tab value="Other clients">

Claude Desktop, ChatGPT and any client with remote MCP and OAuth: add a **custom connector** with `https://your-supercheck-host/api/mcp`. Stdio-only clients can bridge with `npx mcp-remote https://your-supercheck-host/api/mcp`.

</Tab>
</Tabs>

## Approve the connection

The first time a tool connects, your browser opens Supercheck.

<Steps>
<Step>
### Sign in
Sign in if you are not already.
</Step>
<Step>
### Check the app name
An app that proves its identity with a Client ID Metadata Document shows the host that controls it. An app that registered itself shows an amber **Unverified app** warning, because anyone could have chosen its name. Continue only if you just started the connection.
</Step>
<Step>
### Choose one project
The list shows only projects you can access. Each connection is tied to one project; connect again to share another.
</Step>
<Step>
### Approve
Select **Approve**. The tool returns to your editor, connected.
</Step>
</Steps>

The approval screen lists what the app asked for, including the optional `mcp:incidents:write` or `mcp:sre` scopes. Approving grants every scope the app asked for; you cannot approve only `mcp:read`. If an app asks for more than you want to grant, deny it and connect a client that asks for read access only. Approving the same app and project again normally adds to what you approved before. Two approvals for the same app and project at the same moment can drop a scope; if a scope you approved is missing, approve the app again. To remove access, disconnect.

Then try: "Use Supercheck to list the failed runs from today", "Which monitors are down right now?" or "Summarize the most recent incident and its root cause."

## Manage or remove a connection

Open **Account** from the user menu and select **Connected apps**. Each row shows the app, the project and its last sign-in refresh. **Disconnect** removes access at once: the next call is refused, even with a recent token. Tool calls are recorded in the audit log with user, app, project and duration, never arguments or results.

![Connected apps](/screenshots/connected-apps.png)

<Accordions>
<Accordion title="Request requirements" id="request-requirements">

Clients must use Streamable HTTP and send `Accept: application/json, text/event-stream` on POST requests. The public host must match `BETTER_AUTH_URL`, including behind a proxy.

A request with an `Origin` header (browsers always send one) must match the canonical resource origin or an exact origin in `MCP_ALLOWED_ORIGINS`, or the server answers `403 invalid_request_origin`. `MCP_ALLOWED_ORIGINS` is comma-separated exact origins such as `https://app.example.com` or `http://localhost:3000`, with default ports omitted, no wildcards or paths. It is separate from the general CORS policy. Command-line and desktop clients usually send no `Origin`.

</Accordion>
</Accordions>
