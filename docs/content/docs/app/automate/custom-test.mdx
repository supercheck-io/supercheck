Write TypeScript or JavaScript tests for scenarios that do not fit the browser, API or database types. Custom tests run in an isolated environment with the Playwright, HTTP, data and database packages included.

## Create a custom test

<Steps>
<Step>
Go to **Create → Custom Test**.
</Step>
<Step>
Write your script, then **Run** and debug it.
</Step>
<Step>
Select **Save** when it passes.
</Step>
</Steps>

## Example

Set `API_URL` to a test API you control that supports `POST /posts`, `GET /posts/:id` and `DELETE /posts/:id`. Public mock APIs that simulate writes cannot verify this workflow.

```typescript
import { expect, test } from '@playwright/test';

const API_URL = getVariable('API_URL');

// Use serial mode to share state (createdId) between tests
test.describe.serial('posts CRUD', () => {
  let createdId: number | undefined;

  test('creates a post', async ({ request }) => {
    const response = await request.post(API_URL + '/posts', {
      data: { title: 'Playwright', body: 'API example', userId: 1 },
    });

    expect(response.status()).toBe(201);
    const json = await response.json();
    createdId = json.id;
    expect(json).toMatchObject({ title: 'Playwright', body: 'API example' });
  });

  test('fetches the created post', async ({ request }) => {
    // Skip if creation failed
    test.skip(!createdId, 'create step failed');
    
    const response = await request.get(API_URL + '/posts/' + createdId);
    expect(response.ok()).toBeTruthy();
    const json = await response.json();
    expect(json.id).toBe(createdId);
  });

  // Cleanup after all tests in this group
  test.afterAll(async ({ request }) => {
    if (!createdId) return;
    await request.delete(API_URL + '/posts/' + createdId);
  });
});
```

## Reference

- Sandboxed TypeScript and JavaScript execution
- Approved packages including Playwright, Axios, Zod, date-fns, Faker and supported database drivers
- `getVariable()` and `getSecret()` for variables and secrets, `readFile()` and `getFile()` for uploaded files
- Good fits: multi-step workflows, complex data validation, integration tests across services

<Callout>
Tests can reach public hosts over TCP. Private-network destinations are blocked. The filesystem is read-only except `/tmp`.
</Callout>
