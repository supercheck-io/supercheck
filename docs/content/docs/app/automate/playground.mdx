Write, run and debug test scripts in the Playground, with AI suggestions you review before applying.

![Playground Editor](/screenshots/playground-editor.png)

## Editor and runs

The editor is Monaco with TypeScript and JavaScript highlighting, Playwright IntelliSense, live syntax checks and auto-formatting. Check a script here before adding it to a job or monitor.

```mermaid
sequenceDiagram
    accTitle: Playground workflow
    accDescr: Run a script, review its report, verify changes, and save the test.
    autonumber
    participant You as You
    participant App as Playground

    rect rgba(139, 92, 246, 0.08)
        You->>App: Write script or choose template
        You->>App: Select Run
        App-->>You: Status, logs, and report
    end
    opt Run failed
        You->>App: Review edits or AI Fix
        You->>App: Run again to verify
    end
    rect rgba(16, 185, 129, 0.08)
        You->>App: Save the test
    end
```

Use **Cancel** to stop a running test. You can save a draft at any time, even a failing one.

## AI Create

Describe the behavior to test and AI Create suggests a script to review, edit and run. Check the target URL, selectors, credentials, waits and assertions before relying on it.

<Callout type="warn">
AI Create for browser tests is in beta. For best results, **record your test first** with the [Supercheck Recorder Extension](/docs/recorder) or Playwright codegen, then use AI Create to enhance it.
</Callout>

![AI Create Prompt](/screenshots/ai-create-prompt.png)

### Use AI Create

<Steps>
<Step>
Select **AI Create** and describe the test in plain language.
</Step>
<Step>
Select **Generate** and review the streamed script in the diff viewer.
</Step>
<Step>
Select **Apply to Editor**, or **Discard** to close it.
</Step>
</Steps>

![AI Create Result](/screenshots/ai-create-result-dialog.png)

<Accordions>
<Accordion title="Writing effective prompts" id="effective-prompts">

**Good prompts are specific and include:**
- The user action you want to test
- Expected outcomes or assertions
- Any specific elements or data to interact with

**Example prompts:**

| Prompt | Intended Check |
|--------|-------------------|
| "Test login with email user@example.com and password test123, verify dashboard loads" | Complete login flow with form filling, submission, and URL assertion |
| "Check that the /api/health endpoint returns 200 and includes status: ok" | API test with fetch, status check, and JSON body validation |
| "Verify user can add a product to cart, view cart, and see correct total" | Multi-step e-commerce flow with navigation and assertions |
| "Test that the contact form validates required fields and shows error messages" | Form validation test with empty submission and error checking |

</Accordion>
</Accordions>
## AI Fix

After a failed run, AI Fix suggests changes. Apply only changes you understand, then run the test again.

<Accordions>
<Accordion title="Access and limits" id="ai-fix-access">

You need access to the run's project. On Supercheck Cloud, AI Create and AI Fix share an hourly organization usage limit. If you reach it, wait before retrying.

</Accordion>
</Accordions>

![AI Fix Button](/screenshots/ai-fix-button.png)

### Use AI Fix

<Steps>
<Step>
After a failed run, select **AI Fix**. It analyzes the error report and your code.
</Step>
<Step>
Review the original-versus-suggested diff, edit if needed, then **Accept & Apply** or **Reject**.
</Step>
<Step>
Run the test again to verify the change.
</Step>
</Steps>

![AI Fix Result](/screenshots/ai-fix-result-dialog.png)

<Accordions>
<Accordion title="What AI Fix can repair" id="ai-fix-repairs">

AI Fix repairs code-level issues:

| Issue Type | Example | AI Fix Action |
|------------|---------|---------------|
| **Selector Issues** | Element not found, wrong selector | Updates selector to match current DOM |
| **Timing Problems** | Element not visible, timeout | Adds appropriate waits or increases timeout |
| **Assertion Failures** | Expected value mismatch | Corrects assertion or expected value |
| **Navigation Errors** | Page not loading, wrong URL | Fixes URL or adds navigation waits |

</Accordion>
</Accordions>

<Accordions>
<Accordion title="When AI Fix shows guidance instead" id="ai-fix-guidance">

Failures that need manual investigation show a guidance modal with troubleshooting steps instead:

- **Network Issues** — Server unreachable, DNS failures, HTTP 5xx errors
- **Authentication Failures** — Invalid credentials, expired tokens, 401/403 errors
- **Infrastructure Problems** — Database down, service unavailable
- **Permission Errors** — Access denied, insufficient privileges

</Accordion>
</Accordions>

## Test reports

Every run produces a report with debugging artifacts:

![Playground Report](/screenshots/playground-report.png)

| Artifact | Description |
|----------|-------------|
| **Screenshots** | Captured at each step and on failure |
| **Trace** | Interactive step-by-step replay |
| **Console Logs** | Browser console output |
| **Network** | All HTTP requests and responses |

<Accordions>
<Accordion title="Viewing traces" id="viewing-traces">

The Playwright [Trace Viewer](https://playwright.dev/docs/trace-viewer) steps through each action, showing page state before and after, DOM and network timing.

</Accordion>
</Accordions>

## Use variables

Read project configuration, secrets and file-backed test data. See [Variables](/docs/app/automate/variables) for setup.

```javascript

// Regular variables (logged normally)
const baseUrl = getVariable('BASE_URL');
const timeout = getVariable('TIMEOUT');

// Secrets are resolved at runtime and redacted from logs
const apiKey = getSecret('API_KEY');
const password = getSecret('DB_PASSWORD');

// File-backed test data
const usersCsv = readFile('USERS_CSV');

// Using in Playwright
await page.goto(baseUrl);
await page.fill('#password', password);
```

Keep credentials in **Secrets** and use **File** variables for non-sensitive fixtures and datasets. Do not log secret values.
