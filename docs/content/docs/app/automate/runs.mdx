Every test or job execution creates a run with results, logs and artifacts.

![Job Runs](/screenshots/job-runs.png)

## Run status

| Status | Description |
|--------|-------------|
| **Passed** | All tests completed successfully |
| **Failed** | One or more tests failed |
| **Error** | Execution error (timeout, crash, infrastructure) |
| **Cancelled** | Stopped by a user before it finished (stored as an error run, shown as Cancelled) |
| **Running** | Currently executing |
| **Queued** | Waiting to execute |
| **Blocked** | Execution denied by access or spending controls |

## View runs

Open **Automate → Runs** and select a run. The list shows the newest 1000 runs. Search and filters only cover the loaded runs.

The **Triggered by** column shows who started each run:

| Trigger | Shows |
|---|---|
| Manual or CLI | The user |
| Trigger key | The key name and the key owner |
| Schedule | The schedule in plain words, for example **Every 4 hours** or **Daily at 09:00**. Hover to see the cron (UTC). Uncommon schedules show the cron itself |

Runs recorded before this column was added show **Unknown**.

Tests, jobs, monitors, requirements, variables and notification channels show a **Created by** column. It is hidden by default on the jobs and monitors tables. Turn it on from the column menu.

Cancelling a running execution ends the run as **Cancelled**, with details on the run page.

## Run details

Each run includes pass/fail counts and duration, screenshots from browser checks, browser test videos, console and live streaming logs, and a step-by-step trace.

![Run Results and Execution Logs](/screenshots/performance-test-result-logs.png)

## Debug a failure

Open the failed run, read the error message, then check the screenshot at the failure point, the console logs and the network requests.

## AI Analyze

Select **AI Analyze** on a job run to generate an analysis report. You need permission to edit the job or test, as for AI Fix. Viewers cannot run it.

The report has an execution summary, failure analysis, performance insights and recommendations, based on the run data. It supports Playwright jobs (test failures with HTML report context) and k6 jobs (performance metrics and threshold breaches).

Self-hosted: an administrator must [configure an AI provider](/docs/app/deployment/self-hosted#optional-configuration) first.

## Analytics

Open **Automate → Runs** and use the tabs at the top: **All runs**, **Performance (k6)**, and **Browser (Playwright)**. The selected view is kept in the URL (`/runs?view=k6` or `/runs?view=playwright`), so you can bookmark or share it.

Switching projects resets analytics filters, job selection, and any open comparison. Each view loads jobs from the newly selected project.

<Accordion title="Performance (k6) analytics" id="k6-analytics">

The **Performance (k6)** view shows performance metrics for your load tests.

![K6 Analytics](/screenshots/dashboard-k6-analytics.png)

**Filters**

- **Job**: one k6 job or all jobs
- **Period**: the last 30, 60 or 90 days

**Metric Cards**

| Metric | Description |
|--------|-------------|
| **Total Runs** | Number of K6 test executions in the selected period |
| **Passed** | Runs where all thresholds passed, with pass rate percentage |
| **Not passed** | Finished runs that did not pass (failed, error, or blocked). Shows "All passing" only when there are none |
| **Avg P95 Response** | Average 95th percentile response time across runs |
| **Avg Request Rate** | Average requests per second across runs |
| **Avg Response Time** | Mean response latency across runs |

**Charts**

**Response Time Trend**
Area chart of P95 response time across runs, to spot regressions or improvements.

**Request Rate Trend**
Area chart of requests per second across runs.


**Run comparison**

When a job is selected and has 2 or more runs, select **Compare Runs** for a side-by-side comparison.

![Run Comparison Dialog](/screenshots/dashboard-k6-compare-dialog.png)

Pick a **Baseline (Left)** run and a **Compare To (Right)** run. Each dropdown entry shows the pass/fail status, date and time, P95 response time and run ID. The table shows both runs with delta values:

| Metric | Description | Better When |
|--------|-------------|-------------|
| **P95 / P99 / Avg Response** | Latency percentiles | Lower |
| **Total / Failed Requests** | Request counts | Higher / Lower |
| **Request Rate** | Requests per second | Higher |
| **Peak VUs** | Maximum virtual users | Context-dependent |

Deltas are green for an improvement and red for a regression. Select **View k6 Reports** to compare the k6 HTML reports side by side.

![K6 Report Comparison](/screenshots/dashboard-k6-report-comparison.png)

**AI Analyze**

Select **AI Analyze** for an AI performance comparison report: metric comparison, what improved or regressed, potential causes and recommendations.

![AI Performance Analysis](/screenshots/dashboard-k6-ai-report-comparison.png)

Self-hosted: an administrator must [configure an AI provider](/docs/app/deployment/self-hosted#optional-configuration) first.

## Delete a run

Queued or running executions cannot be deleted. Stop the execution first. If deletion fails, the run stays available so you can retry.
