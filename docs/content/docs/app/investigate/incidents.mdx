Incidents are the responder queue for issues that need investigation, evidence review, or verification.

You can create an incident in two ways:

- From **Communicate → Alerts → Signals**, when an alert signal needs investigation.
- From **Communicate → Incidents → New incident**, when the issue did not start from a Supercheck alert.

Both paths create the same incident workspace.

The incident queue uses the same table behavior as Tests and Runs: incident number is a separate sortable column, long titles are constrained, rows open the incident detail page, filters sit in the header toolbar, and pagination is available for larger queues.

## Incident Detail

The incident detail page is intentionally focused. It shows the incident status, mapped service, stored evidence count, and the latest brief without mixing in every investigation control.

The page has three tabs:

- **Investigation** — Run a read-only investigation from stored evidence, with optional live connector tools when a primary service is mapped.
- **Evidence** — Review native Supercheck evidence and citation anchors.
- **Brief** — Read or regenerate the latest evidence brief. Brief generation is kept in this tab instead of the incident header to avoid cluttering the default investigation view.

The Investigation tab includes a readiness checklist. Missing stored evidence links to brief generation, and missing service mapping links administrators to service setup so live connector tools remain properly scoped.

This keeps the responder view simple: first confirm the incident, then run investigation, then review evidence and the summary.

### Copilot

Copilot is available from **Investigate → Copilot** and from the global floating Copilot launcher. Use it for read-only follow-up questions and investigation planning without adding a second chat transcript inside the incident page.

Copilot includes:

- **Citations**: Direct links from chat responses to the specific evidence items anchoring the agent's claims.
- **Incident-scoped verification**: When opened from an incident detail page, the floating Copilot is scoped to that incident. It can inspect stored evidence and, when the user has connector investigation permission, use the same bounded read-only live connector tools as the Investigation tab.
- **Inline charts**: Responses can render bounded `bar`, `line`, and `area` charts when the answer includes connector, evidence, or user-provided numeric series.
- **Slash commands and mentions**: `/health`, `/investigate`, `/evidence`, `/verify`, `@incident`, `@service`, and `@recent-deploy` are read-only context shortcuts.
- **Log context**: Drag text, log, JSON, CSV, or Markdown files into the composer to add local read-only context. Copilot treats dropped files as user-provided context, not verified production state, until corroborated by evidence or connectors.
- **Safe Tool Result Summaries**: Collapsible, read-only summaries of tool executions to keep the chat clean while providing deep context when needed.
- **Standalone history**: Conversations stay in the Copilot console instead of cluttering the incident detail page.

## Incident Lifecycle & Verification

Supercheck supports the incident lifecycle up to the point of remediation:

1. **Triage**: Review alert signals or create a manual incident. Incidents are deduplicated when created from the same alert signal.
2. **Investigation**: Run the read-only investigation from the incident detail page using native evidence and, when enabled, scoped [Connector Layer](/docs/app/investigate/connectors) data.
3. **Recommendation**: The evidence brief and investigation report present cited findings and proposed next steps.
4. **Human Verification**: A responder reviews the findings, makes a decision, and applies the fix outside of Supercheck in their respective systems.
5. **Closed-Loop Verification**: Once the fix is applied, Supercheck validates the resolution by automatically re-running the very monitors or synthetic tests that initially detected the issue.

## Alerts and Incidents

Alerts and incidents intentionally remain separate:

- **Alerts** show notification channels, alert history, and active signals.
- **Incidents** show issues your team has decided to investigate.

This keeps alert noise out of the responder queue while still making it easy to promote a signal into an incident.

## Exporting Reports

For post-incident reviews (PIRs) and compliance, Supercheck allows you to download sanitized investigation reports. 

These exports include bounded evidence text, recommendations, and tool input/output hashes, deliberately excluding raw connector data, credentials, and source URIs to maintain security and data privacy. Export provenance includes item counts and truncation metadata so reviewers know when evidence, tool calls, or recommendations were omitted because of safety limits.
