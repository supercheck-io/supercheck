## Default organization and projects

Sign-up creates one default organization and one default project. There is no menu to create or switch organizations. Owners and admins can rename the organization with the pencil button (**Rename organization**) next to its name on the **Organization** page. Use the project selector and the **Projects** tab to create and switch projects.

You can accept invitations to projects in other organizations and keep your default one. Those projects appear in the project selector under the team name. You can see every active project in a joined team read-only. Project Editor and Project Admin assignments add permissions only in the selected projects. Owning your default organization gives no administrative access to another team. Users who sign up through an invitation join the inviting team without a separate organization.

## Projects

Only organization owners and admins create and manage projects in the UI. Project admins can update their assigned projects through the API.

![Projects List](/screenshots/org-admin-projects.png)

<Steps>
<Step>

Open **Organization** in the sidebar, then the **Projects** tab.

</Step>
<Step>

Select **Create Project**, fill in both required fields in the **Create New Project** dialog, then select **Create Project** again to submit.

| Field | Limit |
|---|---|
| **Name** | Up to 20 characters: letters, numbers, spaces, hyphens, underscores |
| **Description** | Up to 100 characters |

</Step>
</Steps>

![Create Project](/screenshots/org-admin-create-project.png)

Project slugs must be unique. Organization owners and admins can delete a project through the API; the dashboard has no delete action, and the default project cannot be deleted.

## Members

Invite teammates and assign roles. Roles are described in [Roles & Permissions](/docs/app/admin/roles-and-permissions).

<Tabs items={['Invite Member', 'Email Invitation', 'Accept Invitation', 'Signup']}>
<Tab value="Invite Member">

<Steps>
<Step>

Open **Organization** and select the **Members** tab.

</Step>
<Step>

Select **Invite Member**, enter the email address, choose a role, and send.

</Step>
</Steps>

![Invite Member Dialog](/screenshots/org-admin-member-invite-dialog.png)

Invitations are limited per user per hour, and if the limiter is unavailable they are refused with a retry message rather than sent. A pending invitation stops working when the person who sent it is removed, demoted from administrator or leaves, and platform administrator accounts cannot accept invitations.

</Tab>
<Tab value="Email Invitation">

The invited member receives an email with a link to join your organization.

![Email Invitation](/screenshots/org-admin-member-email-invitation.png)

</Tab>

The member accepts the invitation to join the organization.

![Accept Invitation](/screenshots/org-admin-member-invite-acceptance.png)

</Tab>
<Tab value="Signup">

</Tab>
</Tabs>

<Accordions>
<Accordion title="Leave an organization" id="leave-an-organization">

Select a project in the team you want to leave, open your profile menu, choose **Account**, and select **Leave** next to the organization. Confirm with **Leave organization**. This removes your membership and project assignments in that team. Other memberships remain in the project selector. If you have none left, the normal setup flow creates your personal organization and project.

Organization owners cannot leave; transfer ownership or delete the organization first. An administrator must invite you again to rejoin.

</Accordion>
<Accordion title="Delete the organization" id="delete-organization">

Only the organization owner can delete it. Select the trash button (**Delete organization**) next to the organization name on the **Organization** page, read what happens next, type the organization name to confirm, and select **Request deletion**. If you signed in a while ago you are asked to sign in again first, then reopen the dialog and confirm within a few minutes.

Deletion is never immediate. The organization enters a **pending deletion** window of 14 days (self-hosted installations can change it, see [Self-hosted](/docs/app/deployment/self-hosted)):

- **Read-only.** Every member sees a banner with the date. Members can still view and export, but nothing runs, schedules and monitors stop, and nothing can be created, changed or invited.
- **Cancel.** The owner can select **Cancel deletion** in the banner at any time before the date. Schedules and monitors resume. Other members see who can cancel but cannot.
- **Early purge.** A Super Admin can end the window early with **Purge now**, for example to honor a legal erasure request (see [Super Admin](/docs/app/admin/super-admin)). The organization can no longer be cancelled after that.
- **Billing.** A subscription stops renewing and ends at the end of the paid period. Cancelling the deletion turns renewal back on while the period is still running; if the period already ended, subscribe again.
- **Emails.** The owners are emailed when the deletion is requested, 7 days and 1 day before it happens, and when it is complete. Without a mail server (some self-hosted installations) no email is sent and the dialog confirms the date in the app instead.
- **After the window.** Every project, test, job, run, monitor, status page and stored report is deleted permanently, and every member loses access. This cannot be undone.

Audit log entries are kept for 12 months, with email addresses replaced by a hash after 30 days, and then removed. Invoices and payment records stay with the payment provider.

Deletion is postponed, not refused, while the organization has usage that was not billed yet: the purge retries until that usage is settled.

</Accordion>
<Accordion title="Delete and restore a project" id="delete-project">

Organization owners and admins can delete a project from the **Projects** tab: open the row menu, choose **Delete project**, and type the project name. The default project cannot be deleted. The project disappears at once and its jobs and monitors stop. For 7 days it appears under **Recently deleted projects**, where an owner or admin can **Restore** it. After that its tests, runs, monitors, status pages and reports are deleted permanently.

</Accordion>
</Accordions>

## CLI tokens

CLI tokens give project-scoped API access for automation. A token inherits its owner's permissions, so use a separate token for each pipeline or integration.

<Steps>
<Step>

Open **Organization**, then the **CLI Tokens** tab.

</Step>
<Step>

Select **Create Token**. Enter a name unique within the project and, optionally, an expiry date (1 hour to 1 year ahead).

</Step>
<Step>

Copy the generated token and store it securely.

</Step>
</Steps>

A project can have at most 20 active CLI tokens (enabled and not expired). Anyone with token update permission can disable or rename a token, but only the token's owner can re-enable it.

## AI SRE setup

Administrators configure AI SRE from the **Integrations** and **Private Agents** tabs so responders do not set up during an incident. Register services on the top-level **Services** page first, then follow [AI SRE Setup](/docs/app/admin/ai-sre-setup).

## Audit log

The **Audit** tab records who did what and when, for compliance and security review. Search entries, or filter by action and user.

The table shows the newest 100 events first; select **Load older events** to fetch the next page. API clients page the same way with the `cursor` parameter of `GET /api/audit`.

![Audit Log](/screenshots/org-admin-audit-list.png)

<Accordions>
<Accordion title="Recorded actions" id="audit-actions">

The **Action** filter lists the actions recorded in your log, such as login, project created, or CLI token created.

</Accordion>
</Accordions>
