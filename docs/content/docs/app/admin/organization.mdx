Use the **Organization** page in the sidebar to manage projects, members, CLI tokens, AI SRE setup, and the audit log.

![Organization overview](/screenshots/org-admin-overview.png)

## Default organization and projects

Sign-up creates one default organization and one default project. There is no menu to create or switch organizations. Use the project selector and the **Projects** tab to create and switch projects.

You can accept invitations to projects in other organizations and keep your default one. Those projects appear in the project selector under the team name. You can see every active project in a joined team read-only. Project Editor and Project Admin assignments add permissions only in the selected projects. Owning your default organization gives no administrative access to another team. Users who sign up through an invitation join the inviting team without a separate organization.

## Projects

Only organization owners and admins create and manage projects. Project admins can update their assigned projects through the API, not the UI.

![Projects List](/screenshots/org-admin-projects.png)

<Steps>
<Step>

### Open the Projects tab

Select **Organization** in the sidebar, then the **Projects** tab.

</Step>
<Step>

### Create the project

Select **Create Project**. Enter a name (up to 20 characters: letters, numbers, spaces, hyphens, underscores) and a description (up to 100 characters). Both are required. Select **Save**.

</Step>
</Steps>

![Create Project](/screenshots/org-admin-create-project.png)

<Accordions>
<Accordion title="API limits and deletion" id="project-api-limits">

The API accepts longer values: name up to 255 characters, description up to 2000, and an optional slug up to 100. A slug already in use returns a conflict error.

Organization owners and admins can soft-delete a project through the API only. The default project cannot be deleted, and the UI has no delete action.

</Accordion>
</Accordions>

## Members

Invite teammates and assign roles. Roles are described in [Roles & Permissions](/docs/app/admin/roles-and-permissions).

<Tabs items={['Invite Member', 'Email Invitation', 'Accept Invitation', 'Signup']}>
<Tab value="Invite Member">

1. Open **Organization** and select the **Members** tab.
2. Select **Invite Member**.
3. Enter the email address and choose a role.
4. Send the invitation.

![Invite Member Dialog](/screenshots/org-admin-member-invite-dialog.png)

</Tab>
<Tab value="Email Invitation">

The invited member receives an email with a link to join your organization.

![Email Invitation](/screenshots/org-admin-member-email-invitation.png)

</Tab>
<Tab value="Accept Invitation">

The member accepts the invitation to join the organization.

![Accept Invitation](/screenshots/org-admin-member-invite-acceptance.png)

</Tab>
<Tab value="Signup">

Sign up or sign in with the invited email address, then accept the invitation to reach the assigned projects. On Supercheck Cloud, verify your email from the link we send before joining.

![Invitation Signup](/screenshots/org-admin-member-invite-signup.png)

</Tab>
</Tabs>

<Accordions>
<Accordion title="Leave an organization" id="leave-an-organization">

Select a project in the team you want to leave, open your profile menu, choose **Account**, and select **Leave** next to the organization. Confirm the organization name. This removes your membership and project assignments in that team and clears its selected context from all your sessions. Other memberships remain in the project selector. If you have none left, the normal setup flow creates your personal organization and project.

Organization owners cannot leave; transfer ownership or delete the organization first. Leaving needs an interactive browser session, so CLI tokens cannot do it. An administrator must invite you again to rejoin.

</Accordion>
<Accordion title="Delete the organization" id="delete-organization">

Only the organization owner can request deletion. An organization with projects or protected dependencies cannot be deleted through the organization API. Contact your administrator or support to review and remove the related data safely.

</Accordion>
</Accordions>

## CLI tokens

CLI tokens give project-scoped API access for automation. A token inherits its owner's permissions, so use a separate token for each pipeline or integration.

<Steps>
<Step>

### Open the CLI Tokens tab

Select **Organization**, then the **CLI Tokens** tab.

</Step>
<Step>

### Create the token

Select **Create Token**. Enter a name that is unique within the project and, optionally, an expiry date (at least 1 hour ahead, at most 1 year).

</Step>
<Step>

### Copy the token

Copy the generated token and store it securely.

</Step>
</Steps>

A project can have at most 20 active CLI tokens (enabled and not expired). Anyone with token update permission can disable or rename a token, but only the token's owner can re-enable it.

## AI SRE setup

Administrators configure project-level AI SRE from the **Integrations** and **Private Agents** tabs, so responders do not manage setup during an incident. Register services on the top-level **Services** page first. See [AI SRE Setup](/docs/app/admin/ai-sre-setup) for the full flow.

## Audit log

The **Audit** tab records who did what and when, for compliance and security review. Search entries, or filter by action and user.

![Audit Log](/screenshots/org-admin-audit-list.png)

<Accordions>
<Accordion title="Recorded actions" id="audit-actions">

The **Action** filter lists the actions recorded in your log, such as login, project created, or CLI token created.

</Accordion>
</Accordions>
