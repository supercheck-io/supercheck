Self-host Supercheck on one Linux server. One command installs Docker, the isolated test sandbox, and every Supercheck service, then checks that it is healthy.

## Prerequisites

| Requirement | Details |
|-------------|---------|
| OS | Ubuntu 22.04+ or Debian 12+ (x86_64 or arm64) |
| Resources | 2 vCPU and 4 GB RAM minimum; 15 GB free disk minimum (30–50 GB recommended) |
| Access | `sudo` and outbound internet access. Docker and Compose are installed for you |
| Public HTTPS only | A domain pointing at the server (plus a wildcard record for status pages), inbound ports 80 and 443, and an email address for certificate notices |

<Callout type="warn">
**Linux only.** The test sandbox needs the Linux kernel. macOS, Windows, WSL2, and Docker Desktop are not supported.
</Callout>

## Install

<Steps>
<Step>

### Download the installer

```bash
curl -fsSL https://raw.githubusercontent.com/supercheck-io/supercheck/main/deploy/docker/install.sh -o install.sh
```

Read it first with `less install.sh` if you like. Add `--dry-run` in the next step to see the plan without changing anything.

</Step>
<Step>

### Run it

<Tabs items={['Guided', 'Local, no prompts', 'Public HTTPS, no prompts']}>
  <Tab value="Guided">
    ```bash
    sudo bash install.sh --version 1.3.7-canary.16
    ```

    The installer asks only what it cannot detect:

    | Prompt | Default | Notes |
    |--------|---------|-------|
    | `Choose` | `1` | `1` = try it on this server (HTTP on localhost); `2` = public server (HTTPS) |
    | `Domain for Supercheck` | none | Public only. A hostname such as `app.example.com`, not an IP address or URL |
    | `Email for Let's Encrypt notices` | none | Public only |
    | `Continue?` | Yes | Last confirmation before anything is installed |
  </Tab>
  <Tab value="Local, no prompts">
    ```bash
    sudo bash install.sh --version 1.3.7-canary.16 --local --yes
    ```
  </Tab>
  <Tab value="Public HTTPS, no prompts">
    ```bash
    sudo bash install.sh --version 1.3.7-canary.16 --domain app.example.com --email you@example.com --yes
    ```
  </Tab>
</Tabs>

Allow about 10 minutes, mostly image downloads. Re-running is safe: it keeps your existing `.env` and secrets and skips finished steps.

</Step>
<Step>

### Open Supercheck

The installer prints the URL: `https://<your-domain>` for a public install, or `http://localhost:3000` for a local one.

Port 3000 listens on the server only. From your laptop, forward it with `ssh -L 3000:localhost:3000 <user>@<server>`. For HTTPS, the certificate is issued on first visit and can take up to a minute.

Create your account, then add a test and run it.

</Step>
</Steps>

<Callout type="warn">
On a public server, sign-up is open to anyone who can reach the URL. Create your account first, then set `SIGNUP_ENABLED=false` in `.env` (or restrict it with `ALLOWED_EMAIL_DOMAINS`) and recreate the app. See [Optional configuration](#optional-configuration).
</Callout>

### Installer options

| Option | Purpose |
|--------|---------|
| `--local` | Evaluate on this server (HTTP on localhost, port 3000) |
| `--domain <host>` / `--email <address>` | Public HTTPS install; both are required together |
| `--status-domain <host>` | Domain for status pages (default: same as `--domain`) |
| `--yes`, `-y` | Never prompt; fail with a clear message if a value is missing |
| `--dry-run` | Run read-only checks and print the plan; change nothing |
| `--version <x.y.z>` | Release to install (default: the version bundled with the script) |
| `--dir <path>` | Install location (default: `/opt/supercheck`) |
| `--no-prewarm` | Skip importing the ~3 GB worker image into the sandbox; the first test run downloads it instead |
| `--docker-group` | Add the invoking sudo user to the `docker` group (root-equivalent access) |

Exit codes: `0` healthy, `1` failed, `2` bad usage, `3` installed but the health check reports a problem. The log is `/var/log/supercheck/install.log`.

## Verify

Run from `/opt/supercheck/deploy/docker` (or your `--dir`):

```bash
sudo docker compose ps
curl --fail --silent --show-error http://localhost:3000/api/health
```

All services should be healthy and the health endpoint should return `{"status":"ok"...`. For HTTPS, also open `https://<your-domain>/api/health`.

### What gets installed

| Service | Purpose | Host port |
|---------|---------|-----------|
| `app` | Next.js UI and API | `127.0.0.1:3000` |
| `worker` | Test execution in the gVisor sandbox | none |
| `postgres` | Database | `127.0.0.1:5432` |
| `redis` | Job queues | `127.0.0.1:6379` |
| `rustfs` | S3-compatible artifact storage | `127.0.0.1:9000` |
| `traefik` | HTTPS reverse proxy (HTTPS profile only) | `80`, `443` |

Sandboxed execution pods can reach public destinations, but not private network addresses (RFC1918, link-local, CGNAT, tailnet). Use a [Private Agent](/docs/app/deployment/private-agent) when checks need services inside another network.

## Optional configuration

Edit `.env` in `deploy/docker`, then apply it:

```bash
sudo docker compose up -d --force-recreate app worker
```

### Common settings

| Variable | Default | Purpose |
|----------|---------|---------|
| `SIGNUP_ENABLED` | `true` | `false` disables open registration (invited users still work) |
| `ALLOWED_EMAIL_DOMAINS` | empty | Comma-separated signup allowlist, for example `acme.com,acme.org` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM_EMAIL`, `SMTP_USER`, `SMTP_PASSWORD` | unset | Email for alerts and invitations (disabled without `SMTP_HOST`) |
| `AI_PROVIDER`, `AI_MODEL`, `OPENAI_API_KEY` | `openai`, `gpt-6-luna`, unset | AI features and AI SRE. Other providers are listed in the [Docker environment reference](https://github.com/supercheck-io/supercheck/blob/v1.3.7-canary.16/deploy/docker/README.md#environment-variables) |
| `SRE_AUTOMATION_ENABLED` | `false` | Automatic alert triage; can incur provider charges. Set in app and worker. See [AI SRE Setup](/docs/app/admin/ai-sre-setup) |
| `DEVICE_AUTH_ENABLED` | `false` | Let `supercheck login` sign in through the browser. Needs HTTPS (or localhost) |
| `TRUSTED_PROXY_HOPS` | `0` | Extra trusted proxies in front of Traefik (for example a CDN), so rate limits see real client IPs |
| `TRUST_CF_CONNECTING_IP` | `false` | Set `true` only if the server is reachable exclusively through Cloudflare |

To grant your account Super Admin access:

```bash
sudo docker compose exec app node scripts/bootstrap-admin.js your-email@example.com
```

### Connecting AI Tools (MCP, off by default)

Lets AI tools such as Claude, Cursor, and VS Code read one project you choose, over OAuth 2.1 with read-only access. See [Supercheck MCP](/docs/mcp).

1. Set `MCP_SERVER_ENABLED=true` in `.env` and recreate the app: `sudo docker compose up -d --force-recreate app`.
2. Make sure `BETTER_AUTH_URL` is the public HTTPS URL (`http://localhost:3000` is accepted for local use). The Docker setup derives it from `APP_DOMAIN`; the app refuses to start with MCP enabled otherwise.
3. Confirm: `curl -s https://your-host/api/config/app` reports `mcp.enabled: true`, and `curl -si -X POST https://your-host/api/mcp` returns `401` with a `WWW-Authenticate` header.

Set `MCP_DYNAMIC_CLIENT_REGISTRATION=false` to accept only clients that identify themselves with a Client ID Metadata Document. Browser-based clients cannot call the OAuth endpoints (no CORS headers).

### Missing-Region Detection (Optional)

By default a multi-region monitor waits for every region, so one silent region blocks the result. This option closes each run at a deadline and counts silent regions as failed. It is off by default.

1. Add `monitor-control` to `COMPOSE_PROFILES` in `.env` (for example `https,monitor-control`) and run `sudo docker compose up -d monitor-control`. Run exactly one instance.
2. Confirm it is healthy with `sudo docker compose ps monitor-control`.
3. Set `MISSING_CYCLE_CLOSURE_ENABLED=true` in `.env` and recreate the app.

`MISSING_CYCLE_DEADLINE_SECONDS` (default `300`) sets how long a run waits; two check timeouts are added. To turn it off, set `MISSING_CYCLE_CLOSURE_ENABLED=false`, keep `monitor-control` running until open runs have closed, then stop it and remove it from `COMPOSE_PROFILES`.

## Updates

Back up first (see [Backups](#backups)). From `deploy/docker`, set `SUPERCHECK_VERSION` in `.env` to the release you want, then run:

```bash
sudo docker compose pull
sudo env KUBECONFIG_FILE=/etc/rancher/k3s/supercheck-worker.kubeconfig docker compose up -d --wait --wait-timeout 300
```

Migrations run automatically. Keep your data volumes; never run `docker compose down -v` unless you intend to delete the database, artifacts, and queue.

If the restricted worker kubeconfig is not group-readable by the worker's `pwuser` (GID 1001), re-run `sudo bash setup-k3s.sh`, or run this on every host that runs workers. Never apply it to the admin `/etc/rancher/k3s/k3s.yaml`:

```bash
sudo chgrp 1001 /etc/rancher/k3s/supercheck-worker.kubeconfig
sudo chmod 0440 /etc/rancher/k3s/supercheck-worker.kubeconfig
```

<Callout type="warn">
Installations from a release that bundled MinIO must migrate storage to RustFS before updating. Run `migrate-minio-to-rustfs.sh` from your current checkout; see the [deployment README](https://github.com/supercheck-io/supercheck/blob/v1.3.7-canary.16/deploy/docker/README.md#upgrading).
</Callout>

## Backups

Back up PostgreSQL, the `rustfs-data` volume, `.env`, and (for HTTPS) the `traefik-letsencrypt` volume before upgrades. Keep `.env` private and off the server: it holds the database password, `BETTER_AUTH_SECRET`, and `SECRET_ENCRYPTION_KEY`, which you need to read encrypted data.

```bash
install -m 600 /dev/null "$HOME/supercheck-backup.sql" && \
  sudo docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > "$HOME/supercheck-backup.sql"
```

The SQL export does not include files, `.env`, or certificates.
