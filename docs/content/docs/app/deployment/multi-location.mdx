## Setup

<Accordions>
  <Accordion title="Requirements" id="requirements">
    - A running self-hosted instance and Super Admin access.
    - A Linux server per region: Ubuntu 22.04+ or Debian 12+, x86_64 or ARM64, at least 2 vCPU, 4 GB RAM, and 15 GB free disk.
    - Sudo access, `curl`, `bzip2`, and [Docker Engine with Compose v2.24.4+](https://docs.docker.com/engine/install/).
    - VPN or encrypted private connectivity to the main server's PostgreSQL, Redis, and S3 storage. Allow only worker hosts; never expose these services publicly.
    - App, workers, Compose files, and sandbox scripts from the same release. Examples use **1.3.7-canary.16**.

    macOS, Windows, WSL2, and Docker Desktop are not supported for execution workers.
  </Accordion>
</Accordions>

### 1. Configure the main server

In **Super Admin → Locations**, add and enable each region (for example, `eu-central` and `us-east`). Set the main server's `.env`:

```dotenv
WORKER_LOCATION=eu-central
```

In its Compose file, replace the PostgreSQL, Redis, and RustFS localhost port bindings with the server's **private VPN address**:

```yaml
services:
  postgres:
    ports:
      - "10.0.0.10:5432:5432"
  redis:
    ports:
      - "10.0.0.10:6379:6379"
  rustfs:
    ports:
      - "10.0.0.10:9000:9000"
```

From the installation's `deploy/docker` directory, apply the changes. Keep existing HTTPS settings and any custom `-f` option:

```bash
sudo env KUBECONFIG_FILE=/etc/rancher/k3s/supercheck-worker.kubeconfig docker compose up -d
```

### 2. Start a regional worker

On each prepared regional server:

```bash
mkdir -p ~/supercheck-worker
cd ~/supercheck-worker
curl -fsSL -o setup-k3s.sh https://raw.githubusercontent.com/supercheck-io/supercheck/v1.3.7-canary.16/deploy/docker/setup-k3s.sh
curl -fsSL -o docker-compose-worker.yml https://raw.githubusercontent.com/supercheck-io/supercheck/v1.3.7-canary.16/deploy/docker/docker-compose-worker.yml
sudo bash setup-k3s.sh
```

Create `.env` with the location code and credentials from the main server. Use its **private** address and the same database and storage buckets:

```dotenv
WORKER_LOCATION=us-east
SELF_HOSTED=true
SUPERCHECK_VERSION=1.3.7-canary.16
DATABASE_URL=postgresql://postgres:YOUR_DB_PASSWORD@10.0.0.10:5432/supercheck
REDIS_HOST=10.0.0.10
REDIS_PORT=6379
REDIS_PASSWORD=YOUR_REDIS_PASSWORD
S3_ENDPOINT=http://10.0.0.10:9000
AWS_ACCESS_KEY_ID=YOUR_S3_ACCESS_KEY
AWS_SECRET_ACCESS_KEY=YOUR_S3_SECRET_KEY
```

```bash
chmod 600 .env
sudo env KUBECONFIG_FILE=/etc/rancher/k3s/supercheck-worker.kubeconfig docker compose -f docker-compose-worker.yml up -d --wait --wait-timeout 300
```

### 3. Verify regional execution

Confirm the location shows **Active** and the worker is ready, then run a monitor or k6 test in that region and check the reported location. A heartbeat alone does not verify its database, Redis, and storage connections.

## Operations

<Accordions>
  <Accordion title="Execution locations" id="choose-execution-locations">
    | Workload | Location selection |
    |---|---|
    | Monitors | Select regions in the monitor configuration. |
    | k6 tests and jobs | One available region per run; Global lets Supercheck choose. |
    | Playwright tests and jobs | Shared global queue; location settings do not pin execution. |

    Each worker's `WORKER_LOCATION` must match an enabled location code. Use `local` only for a single-server installation.
  </Accordion>

  <Accordion title="Managing locations" id="managing-locations">
    Manage regions in **Super Admin → Locations**. Each needs a unique code matching `WORKER_LOCATION` and a display name.

    **Active** means enabled with a worker heartbeat; **Offline** means enabled without one; **Disabled** prevents new regional work. Keep workers running for monitoring. Disabling a location lets active work drain and retains queued work and its capacity reservation until re-enabled. Playwright uses its global queue.

    Monitors use online, enabled, project-allowed locations. k6 submissions require a matching live heartbeat; wait for a starting worker to connect before retrying `queue_unavailable`.
  </Accordion>

  <Accordion title="Project location restrictions" id="project-location-restrictions">
    Org admins can restrict regions in **Organization Admin → Projects → Location restrictions**.
  </Accordion>

  <Accordion title="Scaling workers" id="scaling-workers">
    Set `WORKER_REPLICAS` in each worker host's `.env`. On the main server, set `RUNNING_CAPACITY` to the total replicas across all hosts and `QUEUED_CAPACITY` to the desired queue limit. Apply with the corresponding Compose start command above.
  </Accordion>

  <Accordion title="Connection settings" id="connection-settings">
    `SELF_HOSTED=true` matches bundled PostgreSQL without TLS. For a database requiring TLS, add `?sslmode=require` to `DATABASE_URL`.

    If the main server uses custom database names, users, S3 region, or bucket names, copy their matching values. See the [worker Compose reference](https://github.com/supercheck-io/supercheck/blob/v1.3.7-canary.16/deploy/docker/docker-compose-worker.yml).

    Keep `.env` private. After changing settings, use `up -d --force-recreate`; `restart` does not reload environment values.
  </Accordion>
</Accordions>
