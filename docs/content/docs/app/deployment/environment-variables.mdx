Reference for the settings an operator can change. The common ones are on [Self-Hosted](/docs/app/deployment/self-hosted#optional-configuration); this page lists them all.

How to apply a change:

- **Docker Compose:** edit `.env` in `deploy/docker`, then run `sudo docker compose up -d --force-recreate app worker`. The bundled Compose files forward the common settings; to set any other variable, add it to the `environment:` block of the `app` or `worker` service.
- **Where it applies:** **App** is the web app, **Worker** is the execution worker, **Both** means set the same value on each. Values that must match are called out.
- Defaults are used when a variable is unset or empty. Invalid numbers fall back to the default unless noted.
- Variables not listed here are internal (set by the installer, the worker or CI) and not supported as settings.

The annotated templates are [`app/.env.example`](https://github.com/supercheck-io/supercheck/blob/main/app/.env.example) and [`worker/.env.example`](https://github.com/supercheck-io/supercheck/blob/main/worker/.env.example). Compose-only variables (ports, bind addresses, `COMPOSE_PROFILES`, `WORKER_REPLICAS`) are in the [Docker environment reference](https://github.com/supercheck-io/supercheck/blob/main/deploy/docker/README.md#environment-variables).

## Core

| Variable | Applies to | Default | Purpose |
|----------|-----------|---------|---------|
| `SELF_HOSTED` | Both | `true` in the bundled stack | Self-hosted mode: no plan limits. Leave `true` |
| `BETTER_AUTH_SECRET` | App | none, required | Session signing secret (`openssl rand -hex 32`) |
| `BETTER_AUTH_URL` | App | none, required | Public URL of the app. Must be the public HTTPS URL when MCP or device login is on |
| `NEXT_PUBLIC_APP_URL` | Both | `http://localhost:3000` | Browser-reachable URL, embedded at build time |
| `APP_URL` | Both | `http://localhost:3000` | Runtime app URL for middleware, emails and worker callbacks |
| `TRUSTED_ORIGINS` | App | empty | Extra origins trusted for sign-in and CSRF checks, comma-separated. Use `CORS_ALLOWED_ORIGINS` for API calls from browser integrations |
| `CORS_ALLOWED_ORIGINS` | App | empty | Extra origins that browser integrations may call the API from. Supports `https://*.example.com` |
| `SECRET_ENCRYPTION_KEY` | Both | none, required | Encrypts stored secrets (variables, connector credentials). Must be identical on the app and every worker. Changing it makes existing secrets unreadable |
| `DEFAULT_PROJECT_NAME` | App | `Default Project` | Name of the project created for a new organization |
| `SUPER_ADMIN_EMAIL` | App | none | Used by `scripts/bootstrap-admin.js` when no email argument is given |
| `SUPERCHECK_VERSION` | Compose, Worker | the release in the checkout | Image tag Compose pulls. The worker reports it as its version |
| `SHOW_COMMUNITY_LINKS` | App | `false` | `true` shows the community link in the header |
| `NEXT_PUBLIC_SOURCE_URL` | App | the upstream repository | Build-time link to the corresponding source. Forks and modified builds must point it at their own source |
| `DEMO_MODE` | App | `false` | `true` flags the instance as a demo to the UI |
| `LOG_LEVEL` | Both | `info` in production, `debug` in development | `trace`, `debug`, `info`, `warn`, `error` or `fatal` |
| `LOG_DB_QUERIES` | App | `false` | `true` logs SQL, in development only |

## Data retention and cleanup

Retention for monitor results, aggregates and job runs comes from the plan limits stored in the database. These variables control the schedule and batch sizes. Each cleanup has `*_ENABLED`, `*_CRON`, `*_BATCH_SIZE` and `*_SAFETY_LIMIT` (maximum rows per run).

| Variable prefix | Default cron | Default batch / safety limit | Notes |
|-----------------|--------------|------------------------------|-------|
| `MONITOR_CLEANUP_` | `0 2 * * *` | `1000` / `1000000` | Monitor results |
| `MONITOR_AGGREGATES_CLEANUP_` | `30 2 * * *` | `1000` / `500000` | Monitor aggregates |
| `JOB_RUNS_CLEANUP_` | `0 3 * * *` | `100` / `10000` | Job runs and artifacts |
| `WEBHOOK_CLEANUP_` | `0 4 * * *` | `1000` / `100000` | Webhook idempotency records |
| `ALERT_HISTORY_CLEANUP_` | `30 4 * * *` | `1000` / `100000` | Also `ALERT_HISTORY_RETENTION_DAYS` (`90`) |
| `AUDIT_LOGS_CLEANUP_` | `0 1 * * *` | `1000` / `100000` | Also `AUDIT_LOGS_RETENTION_DAYS` (`90`) |
| `TELEMETRY_RETENTION_` | `45 * * * *` | `1000` (1 to 10000) / `200000` | Operational telemetry tables |

All cleanups default to enabled. Additional variables:

| Variable | Applies to | Default | Purpose |
|----------|-----------|---------|---------|
| `PLAYGROUND_CLEANUP_ENABLED` | App | `true` | Playground artifact cleanup |
| `PLAYGROUND_CLEANUP_CRON` | App | `0 5 * * *` | Schedule |
| `PLAYGROUND_CLEANUP_MAX_AGE_HOURS` | App | `24` | Age after which artifacts are deleted |
| `MONITOR_AGGREGATION_HOURLY_ENABLED`, `MONITOR_AGGREGATION_HOURLY_CRON` | App | `true`, `5 * * * *` | Hourly monitor roll-up |
| `MONITOR_AGGREGATION_DAILY_ENABLED`, `MONITOR_AGGREGATION_DAILY_CRON` | App | `true`, `15 0 * * *` | Daily monitor roll-up |
| `CREDENTIAL_REVOCATION_RETRY_ENABLED`, `CREDENTIAL_REVOCATION_RETRY_CRON` | App | `true`, `20 * * * *` | Finishes revoking API keys after a password reset. Leave enabled |
| `STATUS_PAGE_DELIVERY_RETENTION_DAYS` | App | `30` | Days notification delivery rows are kept (1 to 3650) |
| `PRIVATE_AGENT_HEARTBEAT_RETENTION_DAYS`, `PRIVATE_AGENT_JOB_RETENTION_DAYS` | App | `7`, `30` | Private agent telemetry |
| `SRE_HEALTH_SNAPSHOT_RETENTION_DAYS`, `SRE_DEPENDENCY_OBSERVATION_RETENTION_DAYS`, `SRE_ALERT_EVENT_RETENTION_DAYS` | App | `90` each | AI SRE telemetry |

| `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` | none | Corporate proxy |
| `NO_COLOR` | none | Any value disables colored output |

## Supercheck Cloud only

Self-hosted installs do not use these: `SENTRY_DSN`, `SENTRY_ENVIRONMENT`, `SENTRY_RELEASE` (error reporting, never loaded when `SELF_HOSTED=true`), `CHATWOOT_*` (support chat), `CRON_SECRET`, and the other variables of the hosted service. Do not set them.
