Trigger jobs, wait for results, and gate deployments on test outcomes from any CI/CD platform.

## Secrets

Set these in your CI/CD platform's secret store:

| Secret | Description |
|---|---|
| `SUPERCHECK_TRIGGER_KEY` | Job-specific trigger key (`sck_trigger_*`) for `supercheck job trigger` |
| `SUPERCHECK_TOKEN` | CLI token (`sck_live_*`) for general API commands and `job trigger --wait` |

Pass the job ID as the argument to `supercheck job trigger`; the CLI does not read a default job ID from an environment variable. Cloud users need no URL setting.

## Pipelines

<Tabs items={['GitHub Actions', 'GitLab CI', 'Docker']}>
<Tab value="GitHub Actions">

### Reusable workflow

```yaml title=".github/workflows/supercheck.yml"
name: Supercheck Tests

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    uses: supercheck-io/supercheck/.github/workflows/supercheck-cli.yml@main
    secrets:
      SUPERCHECK_TRIGGER_KEY: ${{ secrets.SUPERCHECK_TRIGGER_KEY }}
      SUPERCHECK_TOKEN: ${{ secrets.SUPERCHECK_TOKEN }}
    with:
      job-id: ${{ vars.SUPERCHECK_JOB_ID }}
      wait: true
      timeout: 300
```

`SUPERCHECK_TRIGGER_KEY` starts the run. `SUPERCHECK_TOKEN` is only needed here because the example uses `wait: true`.

### Manual setup

```yaml title=".github/workflows/e2e.yml"
name: E2E Tests

on:
  push:
    branches: [main]
  pull_request:

jobs:
  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 24

      - name: Install Supercheck CLI
        run: npm install -g @supercheck/cli

      - name: Run E2E Tests
        run: supercheck --json job trigger ${{ vars.JOB_ID }} --wait
        env:
          SUPERCHECK_TRIGGER_KEY: ${{ secrets.SUPERCHECK_TRIGGER_KEY }}
          SUPERCHECK_TOKEN: ${{ secrets.SUPERCHECK_TOKEN }}

      - name: Deploy Config
        if: github.ref == 'refs/heads/main'
        run: supercheck deploy --force
        env:
          SUPERCHECK_TOKEN: ${{ secrets.SUPERCHECK_TOKEN }}
```

### Deployment gating

Use the CLI exit code to stop the workflow when the run fails, is blocked, or times out:

```yaml
- name: Gate Deployment
  run: |
    supercheck job trigger "${{ vars.JOB_ID }}" --wait
  env:
    SUPERCHECK_TRIGGER_KEY: ${{ secrets.SUPERCHECK_TRIGGER_KEY }}
    SUPERCHECK_TOKEN: ${{ secrets.SUPERCHECK_TOKEN }}
```

### Basic template

```yaml title=".gitlab-ci.yml"
stages:
  - test

supercheck:
  stage: test
  image: node:20-slim
  before_script:
    - npm install -g @supercheck/cli
  script:
    - supercheck health
    - supercheck --json job trigger $SUPERCHECK_JOB_ID --wait
  variables:
    SUPERCHECK_TRIGGER_KEY: $SUPERCHECK_TRIGGER_KEY
    SUPERCHECK_TOKEN: $SUPERCHECK_TOKEN
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```

### With Monitoring-as-Code deploy

Commit `supercheck.state.json` with the project so CI can map local resources to IDs created by earlier deployments. It is scoped to the API origin and actual project. Never commit the transient `supercheck.state.json.lock` file. Keep `SUPERCHECK_TOKEN` in the CI secret store. The CLI checks configured project context before syncing.

```yaml title=".gitlab-ci.yml"
stages:
  - test
  - deploy

supercheck-test:
  stage: test
  image: node:20-slim
  before_script:
    - npm install -g @supercheck/cli
  script:
    - supercheck job trigger $SUPERCHECK_JOB_ID --wait
  variables:
    SUPERCHECK_TRIGGER_KEY: $SUPERCHECK_TRIGGER_KEY
    SUPERCHECK_TOKEN: $SUPERCHECK_TOKEN

supercheck-deploy:
  stage: deploy
  image: node:20-slim
  before_script:
    - npm install -g @supercheck/cli
  script:
    - supercheck diff
    - supercheck deploy --force
  variables:
    SUPERCHECK_TOKEN: $SUPERCHECK_TOKEN
  only:
    - main
```

<Tab value="Docker">

Set `SUPERCHECK_JOB_ID` and the required tokens in your environment. Run the CLI using the official Node.js image:

```bash
# Trigger a job
docker run --rm \
  -e SUPERCHECK_TRIGGER_KEY -e SUPERCHECK_TOKEN -e SUPERCHECK_JOB_ID \
  node:20-slim sh -c 'npm install -g @supercheck/cli && supercheck job trigger "$SUPERCHECK_JOB_ID" --wait'

# Deploy config (mount project directory)
docker run --rm \
  -e SUPERCHECK_TOKEN=$SUPERCHECK_TOKEN \
  -v $(pwd):/app \
  -w /app \
  node:20-slim sh -c "npm install -g @supercheck/cli && supercheck deploy --force"

# Health check
docker run --rm node:20-slim sh -c "npm install -g @supercheck/cli && supercheck health"
```

### Docker Compose

```yaml title="docker-compose.yml"
services:
  supercheck:
    image: node:20-slim
    environment:
      SUPERCHECK_TOKEN: ${SUPERCHECK_TOKEN}
    volumes:
      - .:/app
    working_dir: /app
    entrypoint: ["sh", "-c"]
    command: ["npm install -g @supercheck/cli && supercheck deploy --force"]
```

## Exit Codes

| Code | Meaning | CI/CD action |
|---|---|---|
| `0` | Success | Continue pipeline |
| `1` | General error (test failure, validation) | Block deployment |
| `2` | Auth error | Check token configuration |
| `3` | Config error | Fix `supercheck.config.ts` |
| `4` | API error | Check connectivity |
| `5` | Timeout | Increase `--timeout` value |
| `130` | Interrupted | Stream cancelled with Ctrl+C |

In a non-interactive environment, an operation that requires confirmation refuses with exit code `3` and a `CONFIRMATION_REQUIRED` error. Review the JSON plan, then explicitly pass `--force` for an authorized write. Authentication failures remain exit code `2`.

<Accordions>
<Accordion title="Handle exit codes in GitHub Actions" id="exit-code-handling">

```yaml
# Example: Handle exit codes in GitHub Actions
- name: Run Tests
  id: tests
  continue-on-error: true
  run: supercheck job trigger $JOB_ID --wait
  env:
    SUPERCHECK_TRIGGER_KEY: ${{ secrets.SUPERCHECK_TRIGGER_KEY }}
    SUPERCHECK_TOKEN: ${{ secrets.SUPERCHECK_TOKEN }}

- name: Report Results
  if: steps.tests.outcome == 'failure'
  run: echo "Tests failed — check Supercheck dashboard"
```

## Best Practices

| Practice | How |
|---|---|
| Machine-readable results | Use `--json`; add `--envelope` with `--json` for pagination metadata (default list arrays remain compatible) |
| Inspect before writing | `supercheck diff --json` or `supercheck deploy --dry-run --json` |
| Block until tests finish | Use `--wait`, and set `--timeout` to suit your suite |
| Resume a wait | `supercheck run wait <run-id>` never triggers a new run |
| Least privilege | Use trigger keys (`sck_trigger_*`) for single-job triggers |
| Preview config changes | Run `supercheck diff` in PRs |
| Faster builds | Cache the CLI in your CI/CD environment |
