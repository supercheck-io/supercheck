The Supercheck CLI (`@supercheck/cli`) runs your tests, monitors, jobs and incident workflows from the terminal, CI/CD pipelines and coding agents. See the [package on npm](https://www.npmjs.com/package/@supercheck/cli). CLI releases from 0.3.1 are [Apache-2.0](https://github.com/supercheck-io/supercheck/blob/main/cli/LICENSE); earlier releases retain their original licenses.

## Quick Start

<Steps>
<Step>

### Install

```bash
npm install -g @supercheck/cli
```

</Step>
<Step>

### Sign in

```bash
supercheck login
```

Approve the code in your browser. Or pass a CLI token: `supercheck login --token sck_live_...`

</Step>
<Step>

### Verify and explore

```bash
supercheck whoami
supercheck health
supercheck job list
supercheck monitor list
supercheck test list
```

</Step>
<Step>

### Investigate incidents

```bash
supercheck incident list
supercheck sre ask "Summarize active reliability risks"
```

</Step>
</Steps>

## Choose Your Credential

Most commands use a **CLI token** (`sck_live_*`). `supercheck job trigger` is the exception: it uses a job-specific **trigger key** (`sck_trigger_*`), plus a CLI token only when you add `--wait`.

| Use case | Credential | Variable |
|---|---|---|
| Most commands, `deploy`, `diff`, `whoami` | CLI token | `SUPERCHECK_TOKEN` |
| `job trigger` | Trigger key | `SUPERCHECK_TRIGGER_KEY` |
| `job trigger --wait` | Trigger key and CLI token | both |
| Local runs (`--offline`) | None | — |

## Agent Workflows

| Command | Purpose |
|---|---|
| `supercheck skills [topic]` | Workflow index, or focused guidance: `local`, `sync`, `configure`, `execute`, `investigate` |
| `supercheck skills install` | Write a small skill pointer for an agent (existing files kept unless `--force`) |
| `supercheck capabilities --json` | Local CLI capabilities; add `--online` to verify the current server context (does not establish feature availability or permissions) |
| `supercheck schema config --json` | The installed configuration schema |

`skills` and `schema` work offline. Local runs need no cloud credentials:

```bash
supercheck test run --offline --file ./_supercheck_/playwright/homepage.pw.ts
supercheck job run --id "Nightly E2E" --local --offline
```

Offline execution runs local files and skips server-side validation. Cloud sync still requires a project-scoped CLI token. See [Agent-first operation](./commands#agent-first-operation) for JSON, confirmation and resource ownership behavior, or start with the [Agent Quickstart](/docs/cli/agent-quickstart).
