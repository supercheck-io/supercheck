The Supercheck CLI (`@supercheck/cli`) provides a first-class command-line interface for CI/CD pipelines, automation workflows, monitoring-as-code, and AI-assisted incident response. Use it to manage jobs, tests, monitors, incidents, service topology, variables, and more.

[View the package on npm](https://www.npmjs.com/package/@supercheck/cli). CLI releases from 0.3.1 are [Apache-2.0](https://github.com/supercheck-io/supercheck/blob/main/cli/LICENSE); earlier releases retain their original licenses.

## Key Features

- **Agent guidance** — Read versioned CLI workflows offline with `supercheck skills`; inspect config fields with `supercheck schema config --json`
- **Offline local execution** — Run local Playwright and k6 tests without a Supercheck account or server validation
- **CI/CD Integration** — Trigger jobs, wait for results, and gate deployments
- **Monitoring-as-Code** — Define monitors, tests, jobs, notification providers, variables, tags, and status pages in `supercheck.config.ts`
- **Resource management** — Manage supported resources from the terminal within your permissions
- **JSON Output** — Machine-readable output for scripting with `--json`
- **AI SRE** — Triage incidents, start investigations, stream Copilot answers, and inspect service dependencies
- **Safe Retry & Rate Limiting** — Exponential backoff for rate limits and idempotent failures without replaying uncertain mutations
- **Self-Hosted Support** — Works with any Supercheck deployment

## Quick Start

```bash
# Install globally
npm install -g @supercheck/cli

# Authenticate with your CLI token
supercheck login --token sck_live_...

# Verify connection
supercheck whoami
supercheck health

# List resources
supercheck job list
supercheck monitor list
supercheck test list

# Investigate reliability incidents
supercheck incident list
supercheck sre ask "Summarize active reliability risks"
```

## Agent Workflows

Start with `supercheck skills` for the workflow index, then request focused guidance such as `supercheck skills local`, `supercheck skills sync`, or `supercheck skills execute`. `supercheck skills install` writes a small skill pointer for an agent; it preserves existing files unless `--force` is supplied. These commands work offline.

Use `supercheck capabilities --json` to inspect local CLI capabilities. Add `--online` to verify the current server context. This context check does not establish feature availability or permissions. `supercheck schema config --json` describes the installed configuration schema.

Local runs do not require cloud credentials:

```bash
supercheck test run --offline --file ./_supercheck_/playwright/homepage.pw.ts
supercheck job run --id "Nightly E2E" --local --offline
```

Offline execution runs local files and skips server-side validation. Cloud sync still requires a project-scoped CLI token. See [Agent-first operation](./commands#agent-first-operation) for JSON, confirmation, and resource ownership behavior.

<Callout type="info">
  In CI/CD, set `SUPERCHECK_TOKEN` for general CLI/API commands. For `supercheck job trigger`, set `SUPERCHECK_TRIGGER_KEY`, and add `SUPERCHECK_TOKEN` only when you also use `--wait`.
</Callout>

## Choose Your Credential

Most CLI commands use **CLI tokens** (`sck_live_*`). `supercheck job trigger` is the exception: it uses a job-specific **trigger key** (`sck_trigger_*`) and optionally a CLI token when waiting for completion.

```
supercheck.config.ts          → Defines resources (monitoring-as-code)
SUPERCHECK_TOKEN env var      → Authenticates API requests
SUPERCHECK_TRIGGER_KEY env var → Authenticates job trigger requests
supercheck deploy             → Pushes config to Supercheck API
supercheck job trigger <id>   → Triggers jobs from CI/CD
```
