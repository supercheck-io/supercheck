## Global Flags

These flags are available on all commands and can appear before or after the subcommand:

```bash
supercheck --json job trigger <job-id> --wait
supercheck --quiet whoami
supercheck config validate --json
```

| Flag | Description |
|------|-------------|
| `--json` | Output in JSON format (for CI/CD scripting) |
| `--envelope` | Include pagination metadata with JSON list results; requires `--json` |
| `--show-secrets` | Disable redaction for sensitive fields in command output |
| `--quiet` | Suppress non-essential output (only IDs and errors) |
| `--wide` | Show tables without width limits |
| `--no-color` | Disable ANSI colors |
| `--debug` | Enable debug logging |
| `-v`, `--version` | Show version |

Config-aware commands (for example `config`, `diff`, `deploy`, `pull`, `validate`, `destroy`) accept `--config <path>` to point at a specific config file.

For `sre ask`, `sre brief`, `run stream`, and `test status`, global `--json` produces newline-delimited JSON (NDJSON), one event per line.

List commands keep their existing JSON array shape for compatibility. Add `--envelope` to include pagination metadata. Local test and job runs emit bounded NDJSON `local.result` records in JSON mode. Errors are emitted on stderr. Sensitive fields are redacted by default, including notification provider webhook URLs, Discord and Teams webhook credentials, and provider config headers (monitor target URLs stay visible and credential headers are masked); use `--show-secrets` only when the output can be handled securely.

Creating a trigger key requires `--show-secrets` to display its one-time plaintext value. The command fails before making the request when the flag is absent.

## Exit Codes

| Code | Meaning | Example |
|------|---------|---------|
| `0` | Success | Job completed successfully |
| `1` | General error | Test failed, monitor down |
| `2` | Authentication error | Invalid token, expired token |
| `3` | Configuration error | Missing config, invalid schema |
| `4` | Network / API error | API unreachable, 5xx response |
| `5` | Timeout | Operation exceeded timeout |
| `130` | Interrupted | Ctrl+C during a stream |

An operation that requires confirmation exits `3` when declined or when input closes (`ABORTED`), and exits `3` with `CONFIRMATION_REQUIRED` when confirmation is unavailable in a non-interactive session. Review its plan, then pass `--force` to apply the already-authorized change. Authentication errors continue to use exit code `2`.

## Agent-first operation

### `supercheck skills`

Print the offline workflow index or a focused guide. The guidance is bundled with the CLI version and requires no credentials.

```bash
supercheck skills
supercheck skills local
supercheck skills sync
supercheck skills configure
supercheck skills execute
supercheck skills investigate
```

`supercheck skills install` writes a small `.agents/skills/supercheck/SKILL.md` pointer. Use `--path <directory>` to choose another directory. Existing skill files are preserved unless `--force` is passed.

### `supercheck capabilities`

Report the installed CLI version, local workflow capabilities, and whether credentials are present. Add `--online` to verify the current API context with one request; this does not prove that every server feature is available or that the token has permission for every operation. Diagnostic commands tolerate an invalid project config: an explicit, environment, or stored URL identifies the target and skips config loading. Otherwise a valid config supplies its API URL; if config loading fails, diagnostics warn in human-readable output and fall back to the default API URL.

```bash
supercheck capabilities --json
supercheck capabilities --online --json
```

### `supercheck schema config`

Describe the installed configuration schema without loading repository code. JSON is useful for generating or validating configuration.

```bash
supercheck schema config --json
```

### Machine-readable plans and writes

`diff --json` and `deploy --dry-run --json` return plans on stdout. Successful deploys return per-resource results, including server-assigned IDs and the state-file path. `pull --dry-run --json` describes the remote resources and config path it would write. Other mutation `--dry-run --json` commands return the proposed request payload.

In a non-interactive session, a write requiring confirmation refuses with exit code `3` and a `CONFIRMATION_REQUIRED` error. Review the preview before explicitly passing `--force`. The CLI checks that config organization/project match the authenticated API context before sync operations.

Deploy records returned IDs in `supercheck.state.json`, keyed by API origin and actual organization/project. Share this generated mapping with CI so subsequent deploys manage the same resources. The transient `.lock` coordinates deploys only on a shared local filesystem; do not commit it. Names alone do not establish ownership; pull an existing resource or set its explicit ID. Deploy does not rename local test files.

## Authentication

### `supercheck login`

Authenticate with a CLI token.

```bash
supercheck login --token <token>
supercheck login --token <token> --url https://supercheck.yourdomain.com
```

| Flag | Required | Description |
|------|----------|-------------|
| `--token <token>` | No | CLI token (`sck_live_*` or `sck_test_*`). Without it, the CLI prints setup guidance and exits with authentication error `2`; browser login is not available. |
| `--url <url>` | No | API base URL; otherwise uses `SUPERCHECK_URL`, stored URL, config URL, then the cloud default |

The token is verified against the API before being stored locally.

### `supercheck whoami`

Display the authenticated project, organization, and role. Token identity and expiry are included when your role permits viewing API keys; read-only users can still verify their context.

```bash
supercheck whoami
```

Shows user, token name, API URL, and expiry.

### `supercheck logout`

Clear stored credentials.

```bash
supercheck logout
```

## Configuration

### `supercheck init`

Initialize a new project with `supercheck.config.ts` and `_supercheck_/` folder.

```bash
supercheck init
supercheck init --force              # Overwrite existing config
supercheck init --skip-install       # Skip dependency installation
supercheck init --skip-examples      # Skip example test files
supercheck init --pm pnpm            # Use specific package manager
```

| Flag | Description |
|------|-------------|
| `--force` | Overwrite existing config files |
| `--skip-install` | Skip automatic dependency installation |
| `--skip-examples` | Skip generating example test files |
| `--pm <manager>` | Package manager to use (`npm`, `pnpm`, `yarn`, `bun`) |

### `supercheck config validate`

Validate the configuration file schema. Add `--offline` to validate a local-only config without API credentials. Both modes require an existing config file; `--offline` skips cloud project identity checks.

```bash
supercheck config validate
supercheck config validate --offline
```

### `supercheck validate`

Validate local test scripts using the same rules as Playground.

```bash
supercheck validate
```

### `supercheck config print`

Print the resolved configuration with environment variable expansion. Sensitive provider values, including webhook URLs and config headers, are redacted; monitor URLs remain visible and credential headers are masked. Add `--offline` to print a local-only config without API credentials; both modes require an existing config file.

```bash
supercheck config print
supercheck config print --offline
```

## Jobs

### `supercheck job list`

List all jobs in the current project.

```bash
supercheck job list
supercheck job list --page 2 --limit 10
```

| Flag | Default | Description |
|------|---------|-------------|
| `--page` | `1` | Page number |
| `--limit` | `50` | Items per page |

### `supercheck job get`

Get job details.

```bash
supercheck job get <job-id>
```

### `supercheck job create`

Create a new job.

```bash
supercheck job create --name "Nightly E2E" --tests <test-id> --schedule "0 2 * * *"
supercheck job create --name "Smoke Tests" --tests id1,id2 --type k6 --dry-run
```

| Flag | Required | Description |
|------|----------|-------------|
| `--name` | Yes | Job name |
| `--tests` | Yes | Test IDs (space or comma separated) |
| `--description` | No | Job description |
| `--type` | No | Job runner type: `playwright` or `k6` |
| `--schedule` | No | Cron expression |
| `--dry-run` | No | Preview what would be sent without creating |

Job `--type` selects the runner. Test `--type` uses API types: `browser`, `performance`, `api`, `database`, `custom`.

### `supercheck job update`

Update job configuration.

```bash
supercheck job update <job-id> --name "Updated Name"
supercheck job update <job-id> --schedule "0 3 * * *" --dry-run
```

| Flag | Description |
|------|-------------|
| `--name` | Job name |
| `--description` | Job description |
| `--schedule` | Cron expression |
| `--dry-run` | Preview what would be sent without updating |

Job status is runtime state, not configuration. Use `job run`, `job trigger`, or the dashboard/scheduler to affect execution state.

### `supercheck job delete`

Delete a job with confirmation.

```bash
supercheck job delete <job-id>
supercheck job delete <job-id> --force    # Skip confirmation
```

### `supercheck job run`

Run a job immediately, bypassing the cron schedule.

```bash
supercheck job run --id <job-id>
supercheck job run --id <job-id> --local     # Run locally
supercheck job run --id <job-id> --cloud     # Run in the cloud
supercheck job run --id "Nightly E2E" --local --offline
```

`--local --offline` runs tests referenced by a job in the local configuration without credentials or server-side validation. Browser jobs use the configured Playwright browser. Pass `--playwright-config <path>` to use an existing Playwright configuration.

### `supercheck job trigger`

Trigger a job and optionally wait for completion.

```bash
supercheck job trigger <job-id>
supercheck job trigger <job-id> --wait --timeout 300
supercheck --json job trigger <job-id> --wait
```

| Flag | Description |
|------|-------------|
| `--wait` | Wait for the run to complete |
| `--timeout` | Maximum wait time in seconds (default: 300) |

`supercheck job trigger` requires `SUPERCHECK_TRIGGER_KEY`. If you also use `--wait`, set `SUPERCHECK_TOKEN` with access to read job details and run results in the project. The CLI reads the job before triggering, then polls the accepted run; a trigger key alone cannot wait for the result.

The CLI validates the read token and job before starting a waited trigger. If waiting later fails, use the returned run ID with `supercheck run wait <run-id>` to resume observation without triggering another run.

### `supercheck job keys`

Manage trigger keys for a job.

```bash
# List keys for a job
supercheck job keys <job-id>

# Create a new trigger key
supercheck job keys create <job-id> --name "CI Trigger"
supercheck job keys create <job-id> --name "Temp Key" --expires-in 86400

# Revoke a trigger key
supercheck job keys delete <job-id> <key-id>
```

## AI SRE

AI SRE commands use the active project from the CLI token and preserve the same tenant and RBAC boundaries as the dashboard.

Incident commands accept the number displayed by `incident list` or a UUID. Numbers resolve within the CLI token’s project; they are not row positions. For example, `supercheck sre investigate 1` and `supercheck sre ask "Summarize the strongest evidence" --incident 1`. Use `incident list --json` to see UUIDs.

Manual triage and investigations are enabled by default with a configured AI provider. Existing operator opt-outs remain effective: `503 feature_disabled` identifies the setting to change. Recreate containers after changing `.env`. Automatic AI work remains opt-in.

The plural aliases `incidents` and `services` are also supported.

### Incidents

```bash
supercheck incident list --status investigating --severity sev1
supercheck incident get <incident-number-or-uuid>
supercheck incident timeline <incident-number-or-uuid>
supercheck incident resolve <incident-number-or-uuid> --comment "Traffic restored after rollback"
```

Resolution prompts for confirmation and stores the required comment in the incident timeline and audit log. Use `--force` only in reviewed automation.

### Triage and investigation

```bash
supercheck sre triage <incident-number-or-uuid>
supercheck sre investigate <incident-number-or-uuid>
supercheck sre investigate <incident-number-or-uuid> --live-connectors
supercheck sre brief <incident-number-or-uuid>
supercheck sre brief <incident-number-or-uuid> --idle-timeout 120
```

Deep investigation is asynchronous: a successful command returns an accepted investigation-run ID. Follow progress with `incident get` and `incident timeline`. `--live-connectors` enables configured read-only telemetry tools only when the caller also has `sre_connector:investigate` permission.

### Copilot

```bash
supercheck sre ask "Why did checkout latency increase?"
supercheck sre ask "Summarize the strongest evidence" --incident <incident-number-or-uuid>
supercheck sre ask "Check current telemetry" --incident <incident-number-or-uuid> --live-connectors
```

Copilot is read-only. Use an incident your token can access, and add `--live-connectors` only when you have connector investigation permission. `--idle-timeout` controls stream inactivity (minimum 10 seconds). Ctrl-C cancels the client stream. Global `--json` emits NDJSON events for automation. Streamed errors and AI-provider unavailability return a nonzero exit code for both Copilot and evidence briefs.

### Service catalog

```bash
supercheck service list
supercheck service get <service-id>
supercheck service health <service-id>
supercheck service dependencies <service-id>
```

These commands are read-only and require `sre_service:view`.

## Monitoring-as-Code

### `supercheck pull`

Pull remote resources into local config and files. Config pulls include monitors, jobs, notification providers, variables, tags, and status pages; test pulls also write test scripts under `_supercheck_/`. Pull preserves managed test paths and existing browser and `testMatch` settings. Runner-type changes migrate files with backups; new tests must match configured custom globs or pull stops before writing. When overwriting changed files, pull saves a mode-`0600` backup at `<path>.supercheck-backup.<uuid>`. This includes matching test scripts and config files; if a test file is renamed during pull, the old file is backed up before removal. Backups are retained and must be removed manually when no longer needed.

```bash
supercheck pull
supercheck pull --dry-run
supercheck pull --force
supercheck pull --tests-only
supercheck pull --config-only
```

In JSON mode, the completed pull summary includes `files` and `backups` arrays with the paths written and preserved. `--dry-run` does not write files or create backups.

### `supercheck diff`

Preview changes between local config and server state. Notification provider changes include nested `config` fields such as webhook `bodyTemplate`.

```bash
supercheck diff
```

### `supercheck deploy`

Push configuration to the Supercheck API, including notification provider config and webhook body templates. Renaming an ID-less non-test resource creates a separate resource; the old remote resource remains unless `--delete` is used. Carry its explicit ID or pull it first to update the existing resource.

```bash
supercheck deploy
supercheck deploy --dry-run      # Preview without applying
supercheck deploy --delete       # Delete remote resources absent from config
supercheck deploy --force        # Skip confirmation
```

`--force` skips the confirmation prompt. Keep test scripts as editable source files and review `supercheck diff` before deploying.

### `supercheck destroy`

Tear down all managed resources defined with IDs in the local config, including notification providers.

```bash
supercheck destroy --dry-run      # Preview resources to be deleted
supercheck destroy --force        # Confirm and delete resources
```

> Note: `supercheck destroy` requires `--force` to confirm deletion, or `--dry-run` to preview. Bare `supercheck destroy` errors without `--force`.

### `supercheck upgrade`

Upgrade the CLI to the latest release.

```bash
supercheck upgrade
supercheck upgrade --tag <version>       # Install a specific version
supercheck upgrade --package-manager pnpm  # Use specific package manager
supercheck upgrade --dry-run               # Preview without installing
supercheck upgrade -y                      # Skip confirmation
```

| Flag | Description |
|------|-------------|
| `--tag <tag>` | Release target to install (default: `latest`, accepts explicit versions) |
| `--package-manager <pm>` | Package manager to use (`npm`, `pnpm`, `yarn`, `bun`) |
| `-y, --yes` | Skip confirmation prompt |
| `--dry-run` | Preview the upgrade command without executing |

### `supercheck doctor`

Check that all dependencies and configuration are set up correctly.

```bash
supercheck doctor
supercheck doctor --fix    # Auto-install Playwright browsers; prints install hints for other deps
```

The doctor command checks:
- **Node.js** — runtime availability
- **@playwright/test** — npm package for browser tests
- **Playwright browsers** — chromium binary for local test execution
- **k6** — binary for performance/load tests (optional)
- **Authentication** — whether a valid token is stored
- **Configuration** — whether `supercheck.config.ts` exists and is valid

With `--fix`, doctor installs missing Playwright browsers automatically. For `@playwright/test` and `k6`, it prints the install command to run manually.

`diff` and `deploy` preserve remote resources absent from config by default. Use `diff --delete` to preview pruning, then `deploy --delete` to apply it. Pruning includes resources created outside this config. `--no-delete` remains supported.

### Investigation status and terminal output

Use `supercheck sre status <runId>` to follow a triage or accepted investigation. This requires a matching app release with the investigation-status endpoint.

Use `--wide` for unrestricted table values or `--json` for complete structured payloads. `--no-color` and `NO_COLOR` disable colors. Pipes have no colors or spinners. Interactive stream connections show elapsed waiting time; GET streams retry one failed initial connection. Writes and POST streams are not replayed. Ctrl+C exits 130; stream idle timeouts exit 5.

With `--json`, fatal errors are JSON on stderr with `error`, `exitCode`, and API `status` and `details` when available. `config print` uses indented JSON in human mode, with secret variable values masked. Test create/update summaries omit the script blob; use `test get <id> --include-script` to read decoded source.

Structured SRE output follows the same Field/Value detail-table format as monitors, tests, and jobs. Triage separates run metadata from the complete narrative summary. Copilot answers and evidence briefs have report headings; quiet mode suppresses their content. Quiet detail output resolves IDs from API envelopes, and `--json` takes precedence when combined with `--quiet`.
