---
title: API authentication
description: Token types, security and rate limits for the Supercheck API
---

Send a Bearer token in the `Authorization` header. Public endpoints, such as health checks and published status-page feeds, need no token:

```bash
curl https://app.supercheck.io/api/jobs \
  -H "Authorization: Bearer sck_live_a1b2c3d4e5f6789012345678901234ab"
```

## Token types

| Token type | Prefix | Access | Use |
|------------|--------|--------------|----------|
| **CLI Token** | `sck_live_` or `sck_test_` | Token owner's permissions in one project | CLI, automation, integrations |
| **Trigger Key** | `sck_trigger_` | Single job trigger only | CI/CD pipelines |

## CLI Tokens

CLI tokens are project-scoped and inherit the creating user's permissions.

### Create a token

```bash
POST /api/cli-tokens
Authorization: Bearer <existing-token>
Content-Type: application/json

{
  "name": "CI/CD Pipeline",
  "expiresIn": 7776000  // optional, seconds: 3600 (1 hour) to 31536000 (365 days)
}
```

**Response** (201):

```json
{
  "success": true,
  "token": {
    "id": "uuid",
    "name": "CI/CD Pipeline",
    "key": "sck_live_a1b2c3d4e5f6789012345678901234ab",
    "start": "sck_live_a1b2...",
    "enabled": true,
    "expiresAt": "2026-04-15T10:30:00Z",
    "createdAt": "2026-01-15T10:30:00Z"
  }
}
```

<Callout type="warn">
  The `key` field is returned **only once** at creation time. Store it securely.
</Callout>

### List tokens

```bash
GET /api/cli-tokens
Authorization: Bearer <token>
```

### Enable or disable a token

```bash
PATCH /api/cli-tokens/{id}
Authorization: Bearer <token>
Content-Type: application/json

{ "enabled": false }
```

### Revoke a token

```bash
DELETE /api/cli-tokens/{id}
Authorization: Bearer <token>
```

## Trigger Keys

Trigger keys can only trigger a single job:

```bash
POST /api/jobs/{id}/trigger
Authorization: Bearer sck_trigger_f1e2d3c4b5a6789012345678901234cd
```

Using a trigger key on any other endpoint returns `401`. Missing or invalid credentials return `401`; a valid token without permission returns `403`.

## Keep tokens secure

- Store tokens in your CI/CD secret manager, never in source control.
- Use a trigger key when a pipeline only starts one job.
- Set an expiry for temporary access and revoke unused tokens.
- A project allows at most 20 CLI tokens.
- Tokens stop working when their owner leaves the organization.

## Rate Limiting

Limits depend on the endpoint. The CLI retries `429` responses with exponential backoff.

| Token type | Limit | Window |
|------------|-------|--------|
| Job trigger key | Configurable per key; default 100 requests per 60 seconds | Per key |
| Other endpoints | Operation-specific | As documented by the endpoint |

### Rate limit headers

Rate-limited endpoints may include these headers; do not assume they are present:

```
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1612137600
```

On `429`, `Retry-After` gives the seconds to wait:

```
HTTP/1.1 429 Too Many Requests
Retry-After: 60
```

<Callout>
Organization and billing administration, including member management and creating projects, needs an interactive browser session. Project-scoped CLI tokens get `403` for these, even for organization administrators. Tokens still support scoped organization and project discovery, authentication context and resource operations within their project.
</Callout>
