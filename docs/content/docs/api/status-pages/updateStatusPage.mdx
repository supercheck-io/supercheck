Update settings and/or status of a status page. Requires `status_page:update`. The body is strict: unknown fields, `subdomain` and `customDomainVerified` return 400, and an empty body returns 400 (`No fields to update`).

Order of work: when `status` is `published`, publish preconditions are checked first and nothing is written if they fail (the page must be accessible to your account and have at least one public component, otherwise 403 or 400). Then settings are saved, then the status is changed. If the status change fails after settings were saved, the error message says so.

Custom domains: setting a non-empty `customDomain` that differs from the current one resets verification and requires the feature to be available for your account (403 if not), a deployment configured for custom domains (400), a hostname outside the platform status page domain (400) and not used by another page (409).
